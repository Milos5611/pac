## Stack

- Kubernetes (Minikube)
- Terraform (`hashicorp/kubernetes` 3.x, `hashicorp/helm` 3.x, `hashicorp/random` 3.x)
- Helm charts for the API and the web client (`charts/backend`, `charts/frontend`)
- Postgres 18 (official `postgres:18-alpine` image, deployed by Terraform)
- Okta (login)
- Datadog (optional)

## What gets deployed

| Namespace  | Resources                                                                                       |
| ---------- | ----------------------------------------------------------------------------------------------- |
| `backend`  | Postgres Deployment + PVC + Service `backend-postgres`, Secret `backend-postgres-access` (DB user/password), ConfigMap `backend-config`, Helm release `backend` (API, ingress `conference.backend`) |
| `frontend` | ConfigMap `frontend-config` (`SVELTE_APP_*`), Helm release `frontend` (nginx, ingress `conference.frontend`) |
| `datadog`  | Only when `enable_datadog = true`: Secret `datadog` + Datadog agent Helm release               |

The API runs schema migration and seeding on startup, so the database is ready after the first rollout.

## Prerequisites

- [Minikube](https://minikube.sigs.k8s.io/docs/start/)
- [kubectl](https://kubernetes.io/docs/tasks/tools/)
- [Helm](https://helm.sh/docs/intro/install/) 3.x
- [Terraform](https://developer.hashicorp.com/terraform/install) 1.9 or newer

## 1. Start Minikube

```bash
minikube config set cpus 4
minikube config set memory 8192
minikube config set disk-size 100g

minikube start

minikube addons enable ingress
minikube addons enable dashboard
minikube addons enable metrics-server
```

`minikube start` creates the kubeconfig context `minikube`. Terraform deploys only into that context (see [Target cluster](#target-cluster)).

## 2. Hostnames

Add both hostnames to `/etc/hosts` (on Windows: `C:\Windows\System32\drivers\etc\hosts`).

- **Linux, or a VM driver (hyperkit, virtualbox, qemu, ...):** point them at `minikube ip`.

  ```
  <minikube ip>  conference.frontend conference.backend
  ```

- **macOS or Windows with the Docker driver:** the Minikube IP is not reachable from the host. Point the names at `127.0.0.1` and keep `minikube tunnel` running in a separate terminal while you use the app.

  ```
  127.0.0.1  conference.frontend conference.backend
  ```

## 3. Configure

Non-secret settings live in [`terraform/pac_context.auto.tfvars`](terraform/pac_context.auto.tfvars): Okta issuer and client ID, redirect URL, backend URL, database name.

Secrets are never committed. Datadog is off by default. To enable it:

```bash
cd terraform
cp secrets.auto.tfvars.example secrets.auto.tfvars   # gitignored
# fill in datadog_api_key and datadog_app_key, then set enable_datadog = true
```

You can also export `TF_VAR_datadog_api_key` and `TF_VAR_datadog_app_key` instead of using the file.

The Postgres password is generated by Terraform (`random_password`) and stored in the `backend-postgres-access` Secret.

## 4. Install

```bash
cd infrastructure/terraform
./install.sh          # init, validate, plan, ask for confirmation, apply
./install.sh --yes    # same, without the confirmation prompt
```

On Windows run `install.bat` (also accepts `--yes`).

Then open http://conference.frontend. The GraphQL API is at http://conference.backend/graphql.

### Target cluster

The providers always use an explicit context: `kube_context` (default `minikube`) in `kube_config_path` (default `~/.kube/config`). They never use your shell's current context. `install.sh` refuses to run if that context does not exist in your kubeconfig. To deploy elsewhere, set it explicitly:

```bash
TF_VAR_kube_context=my-local-cluster ./install.sh
```

## Using locally built images

By default the charts pull `mnikolic/pac_mnikolic_api:latest` and `mnikolic/pac_mnikolic_web:latest` from Docker Hub with `imagePullPolicy: Always`. To run your local code instead, build the images, load them into Minikube, and override the image variables.

```bash
# from the repository root
docker build -t pac_mnikolic_api:dev api
docker build -t pac_mnikolic_web:dev client
minikube image load pac_mnikolic_api:dev
minikube image load pac_mnikolic_web:dev

cd infrastructure/terraform
TF_VAR_backend_image_repository=pac_mnikolic_api \
TF_VAR_frontend_image_repository=pac_mnikolic_web \
TF_VAR_backend_image_tag=dev \
TF_VAR_frontend_image_tag=dev \
TF_VAR_image_pull_policy=Never \
./install.sh
```

Alternatively, run `eval $(minikube docker-env)` before `docker build` to build straight into Minikube's Docker daemon, then skip `minikube image load`.

After rebuilding an image with the same tag, restart the pods:

```bash
kubectl --context minikube -n backend rollout restart deployment backend
kubectl --context minikube -n frontend rollout restart deployment frontend
```

## Troubleshooting

```bash
kubectl --context minikube -n backend get pods
kubectl --context minikube -n backend logs deploy/backend
kubectl --context minikube -n backend logs deploy/backend-postgres
helm --kube-context minikube -n backend test backend
```

## Teardown

```bash
cd infrastructure/terraform
terraform destroy -var kube_context=minikube
```

This deletes the namespaces, including the Postgres volume and its data. `minikube delete` removes the whole cluster.
